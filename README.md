# DELTA LAB — 델타포스 총기 개조 시뮬레이터 MVP

React + TypeScript + Vite + Tailwind CSS로 만든 한국어 총기 개조 작업대입니다. 서버·로그인·API 키 없이 브라우저에서 동작합니다.

**가상 샘플 작업대와 출처 기반 전면전 자료를 분리합니다.** 샘플 작업대는 자체 제작한 가상 데이터입니다. 전면전 자료는 DFTTK 사이트 관측과 Aim Sector 공개 빌드에서 수집한 부분 자료이며, 게임 내 검증을 마친 데이터가 아닙니다. 게임 UI·공식 이미지를 사용하지 않으며 샘플 총기 도식은 직접 만든 SVG입니다.

## 실행

Node.js 22.12 이상 또는 24 LTS와 npm을 사용하세요. 이번 환경은 Node.js 24.19.0에서 검증했습니다.

```bash
cd /workspace/1
npm ci
npm run dev
```

일반 PC에서는 첫 줄을 프로젝트 폴더로 바꾸면 됩니다. 개발 서버의 기본 포트는 5173입니다. 서버를 종료하려면 실행한 터미널에서 `Ctrl+C`를 누르세요. 클라우드에서 브라우저로 열 때는 사용 중인 개발 도구의 포트 연결 기능을 이용하세요.

이미 의존성이 설치된 현재 클라우드 환경에서는 `npm run dev`만 실행하면 됩니다. 설치와 실행은 별개이며, 새 작업에서는 서버 프로세스를 다시 시작해야 합니다.

### 서버 없이 HTML 파일로 열기

```bash
npm run build:standalone
```

`dist/delta-lab.html`에 화면·스타일·샘플 데이터를 포함한 단일 HTML 파일이 생성됩니다. 이 파일을 컴퓨터에 내려받아 Chrome 또는 Edge에서 열면 설치나 개발 서버 없이 MVP를 체험할 수 있습니다. `dist/index.html`은 별도 JS/CSS 파일과 HTTP 서버를 사용하는 일반 배포용 파일이므로, 더블클릭해 실행할 때는 **`delta-lab.html`**을 사용하세요.

채팅 답변의 소스 파일 링크는 웹앱 미리보기 주소가 아닙니다. 현재 클라우드 환경 설정용 온보딩 화면은 localhost 웹 미리보기를 지원하지 않습니다. 클라우드의 localhost와 사용자 컴퓨터의 localhost도 서로 다릅니다. 개발 서버 내부 응답 성공만으로 사용자 화면의 미리보기가 연결되었다고 판단하지 않습니다.

## 사용 방법과 구현 기능

1. 왼쪽 목록에서 가상 총기 3종 중 하나를 선택합니다. 한글·영문 이름과 종류로 검색하거나 종류 필터를 사용할 수 있습니다. `/` 키로 검색창에 포커스합니다.
2. 중앙에서 총열·총구·전방 손잡이·개머리판·탄창·조준경 중 슬롯을 고릅니다. 이 6개 슬롯 구성도 샘플이며 실제 게임 구조가 아닙니다.
3. 부착물의 장점과 단점을 확인하고 장착합니다. 각 총기에 지원되는 부품만 표시하며, 충돌하는 부품은 이유와 함께 선택을 제한합니다. 예: 컴팩트 총열 + 롱 소음기.
4. 오른쪽에서 기본값, 개조 후 값, 증감과 부품별 변화량을 비교합니다. 막대 또는 레이더 그래프를 선택할 수 있습니다.
5. 슬롯의 `기본 구성`으로 개별 부품을 해제하거나 `전체 초기화`로 모든 부품을 해제합니다.

총기 변경 시 부착물이 초기화됩니다. 새로고침해도 상태가 초기화됩니다. 저장·불러오기와 추천 기능은 아직 구현하지 않았습니다. 반응형 레이아웃, 키보드 포커스, 안내 대화상자, 감소된 모션 설정을 지원합니다.

## 샘플 데이터 및 계산 원칙

- 데이터는 `src/data/sample.json`에 있습니다. 현재 가상 총기 3종, 부착물 13종입니다.
- 각 레코드에는 `provenance.status`, `source`, `verifiedAt`, `gameVersion`이 있습니다. 현재 모두 `sample`이며 게임 내 확인일과 게임 버전은 `null`입니다. 자체 생성일을 검증일로 표시하지 않습니다.
- 모든 능력치는 **0~100 샘플 점수**이며 높을수록 좋습니다. 유효 거리는 미터, 조작 속도는 밀리초를 의미하지 않습니다.
- 계산: `clamp(기본값 + 장착 부착물 변화량 합계, 0, 100)`. 이것은 실제 게임 계산식이 아닙니다.
- 부품별 변화량은 제한 적용 전 기여도입니다. 합계가 0 또는 100을 넘으면 화면의 최종 증감은 기여도 단순 합과 다를 수 있습니다.
- 장탄수·배율·소음·피해량·사격 속도·실제 탄도나 반동 패턴은 시뮬레이션하지 않습니다. 가상 도식은 총기별로 다르며, 조준경 장착 외의 부품 외형은 반영하지 않습니다.
- `weaponIds`로 총기 호환 대상을, `incompatibleWith`로 동시 장착 제한을 관리합니다. 충돌은 양방향으로 검사합니다.

실제 데이터를 추가할 때는 샘플 파일의 숫자를 교체하는 것만으로 검증이 끝나지 않습니다. 별도 데이터셋과 자료 출처·확인일·게임 버전을 추가하고, 실제 슬롯·단위·보정식에 맞는 계산 전략과 UI 표시를 함께 구현해야 합니다. 샘플과 검증 데이터를 혼합해 실제 게임 성능이라고 표시하지 마세요.

## 전면전 출처 자료

상단 `전면전 실제 자료 (부분 수집)` 탭에서 확인합니다. 현재 기록은 **2026-10-23에 수집된 자료**입니다. 화면 개선이나 재배포 날짜를 원문 확인일로 표시하지 않습니다.

- 총기 이름 목록 66종, 기본 정보가 있는 총기 2종(AKM, M4A1)
- DFTTK에서 관측한 M4A1 후방 손잡이 9종과 슬롯별 표시 변화량. 이 관측을 다른 총기의 호환성으로 확대하지 않습니다.
- Aim Sector 공개 AKM 빌드에 등장하는 부착물 16종. 기본 효과 수치는 없으므로 `미확인`으로 표시합니다.
- 기존 자료에 있는 피해량·사거리(m)·발사 속도(발/분)·장탄수·조준 전환(ms)·질주 후 사격 전환(ms)·조준 이동 속도(m/s)를 추가로 표시합니다. 비어 있는 값은 0이 아닌 미확인입니다.
- 부착물 원문 이름·슬롯·알려진 변화량·출처 링크·자료 확인일을 표시하고, 부착물 이름·슬롯·자료 출처로 필터링합니다. 필터링은 장착 상태를 바꾸지 않습니다.
- 정밀 보정 12건은 특정 AKM 빌드의 참고 사례로만 표시하며 부착물의 기본 효과와 합산하지 않습니다. 기존 개조 코드도 현재 선택에서 생성한 코드가 아닙니다.

능력치 표시값은 알려진 기본값과 부품 변화량의 **참고 합계**입니다. 실제 게임 계산식이나 최종 성능으로 검증되지 않았고, 부품의 효과가 하나라도 미확인인 항목은 최종 참고값도 미확인으로 표시합니다. 피해량·조준 시간 등 기본 정보와 세부 반동은 시뮬레이션하지 않습니다. 사이트 목록 관측과 게임 내 검증을 구분하세요.

2026-10-27에 DFTTK의 공개 HTML·계약·매니페스트와 대표 combat 팩의 구조를 HTTPS로 분석했습니다. [분석 결과](docs/dfttk-analysis.md)와 [데이터 출처/검증 상태](docs/data-sources.md)를 확인하세요. 공개 계약은 `mp`를 전면전으로 정의하며, 동적 슬롯과 정밀 보정·부분 계산 결과를 구분합니다. 데이터 재배포 라이선스는 확인하지 못해 대량 가져오기나 상시 연동은 추가하지 않았습니다. **이번 분석일을 기존 총기 수치의 확인일로 갱신하지 않았습니다.**

### 이번에 추가한 검증·호환성·추천 기반

- 기존 JSON을 유지하고 `warfare-data.ts`에서 정규 모델로 읽습니다. `verified/observed/unknown/sample` 상태를 구분하고 게임 검증 근거·날짜·버전, 유한 수치, 참조 ID와 모드 경계를 검사합니다. 현재 전면전의 게임 내 `verified` 데이터는 없습니다.
- 소스 고유 ID와 DELTA LAB 로컬 ID, 관측된 슬롯 목록과 전체 슬롯, 미확인 기본 부품을 구분합니다. `sourceId`와 `defaultAttachmentId`가 `null`이면 원문에서 확인하지 못한 것입니다.
- 같은 공개 AKM 빌드에서 함께 등장한 부품 구성은 관측 근거로 선택할 수 있습니다. 서로 다른 빌드의 부품을 섞어 동시 장착 근거가 없으면 `unknown`으로 선택을 보류합니다. 장착 불가능이라고 단정하지 않습니다. 명시적 배제/선행 부품 규칙은 엔진이 지원하지만 실제 자료에는 아직 수록되지 않았습니다.
- 선택 부착물 요약과 부품별 기여도는 검색 필터 밖에서도 확인·해제할 수 있습니다. 선행 부품 규칙이 있는 경우 해당 부품을 해제하면 알려진 종속 부품도 함께 제거하는 로직을 갖췄습니다.
- 5개 플레이 스타일 가중치와 자체 점수 모델 인터페이스를 준비했습니다. 점수는 게임 공식 성능 점수가 아닙니다. 게임 검증 수치·완전한 슬롯/호환성·검증된 계산 전략이 없으므로 현재는 추천 보류 이유만 표시하며 조합이나 점수를 생성하지 않습니다. 상위 3개 탐색은 후속 구현입니다.

`src/data/warfare_seed.json`은 기존 총기 목록·기본값·공개 빌드 기록이고, `src/data/dfttk_grips.json`은 DFTTK 관측 기록입니다. 각 관측의 출처와 날짜를 유지하고, 확인하지 못한 자료나 숫자를 새로 만들지 마세요. 신규 원문 수집은 `dfttk.com` 네트워크 접근이 필요하지만, 웹앱 자체는 저장된 JSON을 사용하므로 DFTTK에 실시간 접속하지 않습니다.

## 빌드 및 테스트

```bash
npm run build
npm test
npm run test:e2e
```

- 빌드는 TypeScript 검사 후 `dist/` 정적 산출물을 생성합니다.
- 단위 테스트는 Vitest로 계산·호환성·JSON 참조 무결성을 검사합니다.
- E2E 테스트는 Playwright로 **빌드된 앱**을 실행하여 데스크톱 및 모바일 크기의 Chromium에서 검증합니다. 먼저 `npm run build`를 실행해야 합니다.
- `/usr/bin/chromium`이 있으면 자동 사용합니다. 다른 브라우저 경로는 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 환경변수로 지정할 수 있습니다. 설치된 브라우저가 없는 일반 PC는 `npx playwright install chromium`을 한 번 실행하세요. 다운로드에는 Playwright의 공식 배포 도메인 접근이 필요합니다.
- 화면 캡처와 실패 추적은 무시된 `test-results/` 아래에 생성됩니다. 캡처 성공은 기능 검증 개수에 포함하지 않습니다.
- 모바일 테스트는 Chromium의 모바일 에뮬레이션입니다. iOS Safari·Firefox와 실제 휴대전화는 아직 검증하지 않았습니다.

프로덕션 빌드를 미리 확인하려면 `npm run preview`를 실행하세요. `dist/`는 정적 호스팅할 수 있도록 상대 경로로 빌드합니다. 공개 배포 주소는 https://eogeonut.github.io/1/ 입니다.

### GitHub Pages 웹 배포

`.github/workflows/pages.yml`에 배포 절차가 있습니다. `main`에 push하거나 GitHub Actions에서 수동으로 실행하면 의존성 설치 → 단위 테스트 → 웹앱 빌드 → Pages 배포 순으로 진행합니다. 배포에는 GitHub Actions 기본 토큰을 사용하며, 소스에 개인 토큰을 넣지 않습니다.

GitHub 저장소 Settings → Pages의 Build and deployment → Source를 **GitHub Actions**로 설정해야 합니다. 최초 활성화는 저장소 설정 권한이 필요하며 일반 Actions 토큰만으로 자동 활성화되지 않습니다. 저장소 요금제·조직 정책에 따라 Pages 사용 가능 여부가 달라질 수 있습니다.

실제 공개 주소는 성공한 배포 작업의 `github-pages` 환경에서 확인하세요. URL이 예상된다는 것만으로 배포 성공을 의미하지 않습니다. 공개 페이지에서 총기 선택과 부착물 변경을 확인한 뒤 배포 완료로 판단합니다.

배포 후 `verify` 작업이 공개 주소에서 데스크톱·모바일 크기의 Chrome을 열어 HTTP 200, 페이지 표시, 장착에 따른 점수 변화, 초기화, 총기 변경과 가로 넘침 여부를 검사합니다. TLS 검증을 유지합니다. 개발 환경의 외부 네트워크 정책과 무관하게 GitHub 실행기에서 실제 배포 주소를 검증하며, 결과는 작업 요약에 기록됩니다. 수동 검증은 `LIVE_URL=https://배포주소/ npm run test:live`로 실행할 수 있습니다.
