# 데이터 출처와 검증 상태

## 데이터셋 경계

| 파일 | 성격 | 원자료 확인일 | 범위 |
| --- | --- | --- | --- |
| `src/data/sample.json` | 가상 `sample` | 게임 확인일 없음 | 기능 검증용 3종 총기·13부품. 전면전과 혼합 금지 |
| `src/data/warfare_seed.json` | 기존 외부 관측 | 2026-10-23 | 총기 이름 66개, 기본값 2종, AKM 예시 부품 16개, 보정 사례 12건, 공개 빌드 코드 70개 |
| `src/data/dfttk_grips.json` | 기존 DFTTK 편집기 관측 | 2026-10-23 | M4A1 후방 손잡이 9개. 다른 총기 호환성으로 확대하지 않음 |
| `docs/observations/dfttk-2026-10-27.json` | 이번 HTTP 분석 증거 | 2026-10-27 | 공개 리소스 응답·크기·해시. 게임 데이터의 새 검증일이 아님 |

원본 JSON을 중복 정규화 JSON으로 복제하지 않는다. 타입·어댑터를 통해 공통 모델로 읽으며, 네이티브 사이트 ID를 확인하지 않은 기존 로컬 ID는 로컬 ID로 명시한다. 단순 목록 등장은 총기 수치나 호환성의 검증이 아니다.

## 상태 정의

- `verified`: 같은 게임 버전·모드에서 실제 게임 내 검증을 마쳤고, 검증 날짜와 근거가 존재함.
- `observed`: 외부 공개 자료에서 관측한 정보. 게임 내 검증으로 격상하지 않음.
- `unknown`: 값·조건·출처 등을 확인하지 못함. `null`을 유지하며 0이나 "제한 없음"으로 변환하지 않음.
- `sample`: 자체 제작한 가상 데이터. 실제 전면전 추천·합산에 사용하지 않음.

현재 전면전 자료에는 게임 내 `verified` 기록이 없다. 관측한 이름·기본값·부품 효과·호환성·보정 가능 여부의 상태를 각각 구분한다. "명시적 충돌 규칙이 없음"은 "충돌이 없음"이 아니다. 같은 공개 빌드에서 함께 등장한 기록은 관측 조합 근거일 뿐 게임 검증이 아니다.

## 버전과 단위

기존 자료의 `S11 midseason` 표기는 당시 외부 자료의 표기다. 이번 매니페스트의 자료 버전 `20261025-ammo-effects.2`나 `gameBuildVersion=unknown`으로 기존 게임 자료를 덮어쓰지 않는다. 자료 버전과 게임 빌드 버전은 별개다. 각 기본값의 m/ms/m/s/발/분 단위를 유지하며, 4개 능력치 막대 점수와 혼합하지 않는다.

알려진 부착물 막대 변화 합계는 `reference-additive` 계산이며, 게임 공식으로 확인한 항목은 아직 없다. 기본 수치나 부착물 효과 하나라도 미확인이면 해당 참고 최종값은 `null`이다. 정밀 보정은 별도의 참고 사례이며 기본 효과로 합산하지 않는다.

이번 조사에서 코드·전체 데이터의 재배포 라이선스는 확인하지 못했다. 자동 수집/상시 호출은 추가하지 않는다. 자료 확장 전 제공자에게 허용 범위·출처 표기·버전 배포 조건을 확인하고, 기본 파츠·슬롯 트리·충돌·종속·세부 단위·게임 내 검증 증거를 확보해야 한다. 외부 페이지의 동적 상태를 고정된 전체 호환성 데이터라고 추정하지 않는다.

## 구현한 모델과 검사

`src/types/warfare.ts`의 모델을 `warfare-data.ts`에서 기존 JSON으로 생성한다. 중복 `weapons.json`/`attachments.json`은 만들지 않았다. 기존 `warfare.ts`의 공개 이름은 호환 진입점으로 유지한다. `verified` 출처는 게임 검증일·게임 버전·게임 테스트 근거가 필요하며 웹사이트 관측만으로 상태를 승격하지 않는다.

`sourceId:null`은 사이트 고유 ID가 미확인이라는 뜻이다. 기존 `warfare:이름`, `dfttk:...`, `akm:...`는 DELTA LAB 로컬 ID다. 슬롯의 `defaultStatus:unknown`과 `defaultAttachmentId:null`은 기본 부품을 모른다는 뜻이며, 기본 부품이 없다고 확정한 값이 아니다. 정밀 보정 가능 여부도 `tunable:null`을 유지한다.

공개 예시의 `confirmed_in_build`가 같으면 같은 구성에서 함께 등장한 관측 그룹으로 정규화한다. 이는 원자료에 있던 `standard/hipfire`의 관계를 읽는 것이며 새로운 호환 규칙을 추정한 것이 아니다. 그룹 밖 혼합은 미확인으로 보류한다. 명시 배제·종속 규칙을 처리할 수 있지만 현재 실제 규칙 배열은 비어 있다. 배제·종속 테스트용 규칙은 테스트 메모리에서만 생성하고 원자료에 넣지 않는다.

추천의 `delta-lab-weights-v1`은 4개 막대 지표의 10점, 사거리 10m, 조준 이동 속도 1m/s를 **자체 평가 기준 구간**으로 사용한다. 게임의 최대값이나 보정 공식이 아니다. 가중 변화의 기준점은 50점이며 0~100으로 평가한다. 관측/미확인 값은 점수 입력으로 받지 않으며, 현재는 검증된 게임 계산 전략도 없어 실제 추천과 점수를 내보내지 않는다.
