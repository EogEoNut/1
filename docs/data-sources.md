# 전면전 기본 총기 자료 출처와 수집 상태

## 현재 결과 (2026-10-28)

전면전 기본 총기 데이터베이스의 **대상 출처**는 [나무위키 델타 포스(2024)/무기](https://namu.wiki/w/델타%20포스(2024)/무기)다. 그러나 이 환경의 정상 HTTPS 요청이 프록시 CONNECT 단계에서 `403 Forbidden`으로 차단됐다. 원문을 읽지 못했고 우회·미러·다른 사이트 수집을 하지 않았다. **나무위키 기반 총기 자료를 수집했다고 주장하지 않는다.**

| 항목 | 결과 |
| --- | --- |
| 수집된 전면전 총기 | 0종 |
| 종류별 수집 수 | AR·SMG·LMG·DMR·SR·SG·권총 등 모두 0종 |
| 필수 수치 전체 확인 / 일부 확인 | 0종 / 0종 |
| 미수집 범위 | 문서 전체. 총기 존재·분류·모든 수치·사격 모드·버전·시즌 |
| 원문 확인일 / 게임 버전 | null / null |
| 접근 시도일 | 2026-10-28 (원문 확인일이 아님) |
| 문서 라이선스·출처 표기 조건 | 원문 접근 제한으로 확인하지 못함. 등록 전 별도 확인 필요 |

존재가 확인되지 않은 총기는 빈 수치 행으로도 등록하지 않았다. 기존 목록을 새 출처로 바꾸어 쓰지 않는다. 추후 원문이 정상적으로 확인되거나 사용자가 확인 가능한 자료를 제공하면 기본 총기만 등록한다.

## 데이터 파일과 제거 범위

| 파일 | 성격 | 현재 범위 |
| --- | --- | --- |
| `src/data/warfare_namuwiki.json` | 독립 전면전 데이터베이스와 수집 상태 | `weapons: []` |
| `src/data/sample.json` | 자체 제작 가상 샘플 | 가상 총기 3종, 부착물 13종 |
| `src/data/weapon-images.json` | 사용자 이미지 경로 | 빈 객체 |

Aim Sector의 총기 목록, 기본값, 부착물 예시, 정밀 보정 사례, 개조 코드, URL·출처 메타데이터와 전용 정규화 로직을 제거했다. `warfare_seed.json`을 삭제하고 신규 파일로 로더를 교체했다. DFTTK 자료도 복구하지 않는다. Git 과거 이력은 변경하지 않는다. 삭제 정책을 설명하는 문서와 회귀 검사 외에 삭제 출처의 자료를 남기지 않는다.

## 새 레코드와 검증

`src/types/warfare.ts`의 정규 모델을 사용한다. ID·표시 이름·한국어/영어 이름·분류·Warfare 모드·기본값·사격 모드·출처와 확인일·게임 버전·검증 상태를 기록한다. 총구 초속(`muzzle_velocity_mps`, m/s)을 지원한다. 기본 몸통 피해량은 부위별 피해량과 구분하고 모호하면 null로 둔다. 기본 장비 변경이나 과거 시즌 값을 섞지 않는다.

- `observed`: 실제로 읽은 외부 자료. 각 레코드에 출처 URL과 확인일이 필요하다. 게임 내 직접 검증이 아니다.
- `verified`: 동일 모드·버전의 게임 내 직접 검증 근거·날짜가 필요하다.
- `unknown`: 미확인. 미확인 수치와 번역·사격 모드는 null이다.
- `sample`: 가상 샘플 전용. 실제 자료 로더는 혼입을 거절한다.

현재는 레코드 자체가 없으므로 observed/verified 총기도 없다. 파일의 대상 출처와 접근 실패 기록은 총기 관측 근거가 아니다. ID·정규화 이름 중복, 모드, 출처 날짜, 유한 숫자/null, 슬롯·부품·규칙 참조를 검사한다.

## 유지한 코드

부착물 선택 UI, 호환성 검사, 참고 합산·기여도, 추천 준비 엔진을 보존했다. 전면전 부착물·관측 조합·규칙·보정·코드는 비어 있으며, 화면에는 `부착물 데이터 미등록 · 추후 업데이트 예정`을 표시한다. 추천 알고리즘과 정밀 보정 기능은 이번에 추가/변경하지 않는다. 엔진 검사는 외부 자료와 무관한 테스트 전용 가상 입력을 사용하며 앱에 포함하지 않는다.

기존 독자 제작 이미지 도식과 사용자 이미지 등록 구조를 유지했다. 신규 총기 이미지 수집은 하지 않았다. [자료 등록 안내](manual-data.md)를 참고한다.
